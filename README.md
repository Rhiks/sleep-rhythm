# 睡眠节律跟踪（本地应用）

纯静态应用。网站负责发送页面和更新文件，健康数据只在浏览器本地处理、保存，不上传到 GitHub 或其他服务器。装到 iPhone 主屏幕后可以全屏、离线使用。

## 晨间首页 · morning-7

第一屏显示质量提示、已记录睡眠、深睡比例及分钟数、睡眠 HRV、睡眠心率。HRV、心率和深睡分别与自己的近期水平比较；REM、已记录清醒、分期覆盖和具体判断依据可展开查看。起床偏晚只作附加信息，不会覆盖恢复信号偏弱的标题。

**不足 3 小时的记录按用户设置跳过**，不纳入首页、趋势均值或个人基线，原始记录保留以便备份。达到 3 小时且已经结束的记录继续展示；例如记录了 8 小时，另有 32 分钟未记录，不会整晚停评。未记录时段不等于清醒，也不等于没有深睡。缺口超过记录区间 10% 时降低对整晚的置信度，仍展示和分析已记录部分。

深睡比例以“核心睡眠 + 深睡 + REM”为分母，并同时给出分期覆盖率。未分期睡眠与没有记录的空白是不同概念。深睡分钟更多与比例更低可以同时出现，但不能据此判断整体恢复更好。缺失分期不填零；真正记录到的 0 分钟深睡保留为零。

个人基线采用所查看夜晚之前 28 个日历日的中位数，每个指标至少需要 5 晚有效值，排除当晚、未来、不足 3 小时和无效总量；同一日期不重复计数。深睡比较另需分期覆盖至少 80%。存在记录缺口但有有效累计时长的夜晚不再被一律踢出基线。页面列出各指标各自的样本数。个人基线是自己的近期参照，不等于健康目标或医学正常范围。

### 透明的产品提示规则，不是医学评分

深睡比例下降至少 max(2 个百分点，个人基线的 15%)、HRV 下降至少 20%、睡眠心率升高至少 5 次/分，会各自触发关注提示。HRV 下降至少 35% 或心率升高至少 10 次/分标为明显偏离；深睡分钟数少于基线至少 15 分钟作补充。高 HRV 或较多深睡不能抵消其他不利信号。总睡眠超过 10 小时并且比个人基线长至少 90 分钟时提示偏长，不因多睡而加分；无基线时超过 10 小时也只提示偏长。

不足 6 小时、6–7 小时、已记录清醒超过 30 分钟或已记录区间睡眠占比低于 85% 分别提示时长偏少或睡眠断续。所有上述切点都是本应用的产品阈值，没有声称经过临床评分验证。“已记录睡眠 /（已记录睡眠 + 清醒）”不含未记录缺口，不冒充临床睡眠效率。

“精神不错 / 一般 / 仍然困倦”保存在本机，并实际参与质量提示；再次点击可取消。“仍然困倦”不会被时长达标覆盖。手表分期及 HRV 都有测量和采样限制，提示不是疾病诊断；长期长睡仍不解乏需要专业评估，而不是仅看某一比例调整补剂。

日期选择器和近 7 个日历夜的小卡可查看历史。昨夜没有可用记录时明确提示，并展示真实日期，不把更早的记录冒充昨夜。旧备份、标签、目标和醒后感受继续兼容。离线缓存版本与现有资源 URL 参数独立更新；缓存升级不清空 localStorage。

验证命令：`node --test tests/*.test.cjs`。测试使用虚构数据，仓库不包含个人健康备份。

## 一、装到主屏幕

把整个应用目录托管到 HTTPS 静态站点，包含 `index.html`、`morning.css`、`sleep-insights.js`、`morning-view.js`、`sw.js`、`manifest.webmanifest` 和三个 `icon-*.png`。不要上传健康导出或备份 JSON。

GitHub Pages：仓库 Settings → Pages → Branch 选择 `main`、目录 `/root`。iPhone 用 Safari 打开部署网址，分享 → 添加到主屏幕，再从图标打开应用。“怎么更新数据、备份与恢复”→“恢复备份”可导入此前保存的 JSON。Safari 页面和主屏幕应用的存储环境可能不同，日常固定使用同一个入口。

## 二、日常更新：快捷指令

在“快捷指令”中新建“睡眠更新”，依次添加：

1. **查找健康样本**：类型为睡眠，开始日期在过去 5 天，按开始日期从早到晚排序。
2. 可选：分别查找心率、呼吸频率、心率变异性、血氧饱和度、静息心率、日照时间，日期范围相同。
3. **文本**：使用下面的分段格式，方括号处插入对应的样本结果属性。每项一行。每个日期变量使用自定格式 `yyyy-MM-dd HH:mm:ss`。睡眠四段必须保留，未查询的可选指标整段删去。

```
#sleep
[睡眠样本 → 开始日期]
#sleep_end
[睡眠样本 → 结束日期]
#sleep_src
[睡眠样本 → 来源]
#sleep_val
[睡眠样本 → 值]
#hr
[心率样本 → 开始日期]
#hr_val
[心率样本 → 值]
#rr
[呼吸频率样本 → 开始日期]
#rr_val
[呼吸频率样本 → 值]
#hrv
[心率变异性样本 → 开始日期]
#hrv_val
[心率变异性样本 → 值]
#ox
[血氧样本 → 开始日期]
#ox_val
[血氧样本 → 值]
#rhr
[静息心率样本 → 开始日期]
#rhr_val
[静息心率样本 → 值]
#daylight
[日照样本 → 开始日期]
#daylight_val
[日照样本 → 值]
```

4. **拷贝至剪贴板**，输入为上一步文本；也可以存成 `sleep-feed.txt`。

早上运行快捷指令后，在应用中点“从剪贴板更新”，或“导入”选择文本文件。快捷指令本身需要在 iPhone 上配置；网站不能直接读取 Apple 健康。未提供的可选生命体征不会在更新已有夜晚时被清空。

## 三、完整更新

iPhone“健康”→ 头像 →“导出所有健康数据”，在应用中导入所得 ZIP。解析发生在本机。步数、静坐时长和午后心率等指标来自完整导出。

## 四、备份

页面底部“导出备份”。清除网站数据或删除应用可能导致本地记录丢失，定期保存备份；更新静态网页或离线缓存本身不会删除健康记录。
